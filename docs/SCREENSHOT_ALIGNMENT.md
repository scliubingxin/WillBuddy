# WillBuddy 0.6.0 · 截图内容与交互接续

2026-10-21 根据用户提供的两张截图独立调整实现。截图展示的是静态画面，不代表已验证参考产品的全部行为。未复制参考产品代码、图标或界面资产。

| 截图中可观察的组织方式 | 本轮实际实现 | 边界 |
| --- | --- | --- |
| WorkBuddy 的任务导航、历史任务和当前任务状态 | 历史任务筛选、当前任务选中、折叠菜单、实际请求状态与耗时 | 不模拟积分、套餐、账户或虚构运行状态 |
| 执行过程可展开，命令结果位于对话中 | 每轮 runId 将真实工具审计关联到该轮；显示待确认、执行、拒绝、错误、输出和退出码 | 不展示伪造的“深度思考”；原生审批仍由系统窗口完成 |
| Quick 的对话与 Session tabs 并排 | 右侧任务工作区、最多 8 个成果/文件页签、关闭/重开、原文与阅读视图、导出、字号 | 当前为文本/Markdown，不是完整 Office、图片或网页编辑器 |
| 在成果旁继续沟通和修改 | 从回复/成果/授权文件打开预览；“继续修改”将可见原文加入草稿，保留已有草稿，用户发送后才调用模型 | 长文本仅加入前 14000 字符，并明确标注；不会静默修改本地文件 |
| 输入区随时可用，并有上下文入口 | 输入区固定在对话底部；@ 从授权目录选择资料，/ 选择实际已有智能体；键盘上下键/Enter/Esc；发送、停止 | 附件仍只支持原有受限文本/代码文件；没有虚构技能、连接器或语音按钮 |
| 长任务过程中仍可阅读与操作 | 运行通知刷新保持输入焦点、选区、草稿、滚动位置与展开记录；任务间预览页签隔离 | 草稿和页签只保留于当前窗口，不是持久化任务队列；退出不会自动重放操作 |

主题继续使用用户原始蓝红 logo，主背景、侧栏、卡片和弹窗为 #FFFFFF，主操作使用 #0078CB。没有恢复参考截图里的紫色或灰色大背景。

验证分层：28 项 Node/JSDOM 回归测试；真实 Chromium Headless Shell 的界面布局、键盘与导出测试；真实隔离世界 DOM 与 CDP 输入/表单跳转测试。后两项仍使用确定性原生桥、审批和模型协议夹具，不能称为 Electron/Mac 原生、真实模型或真实账户集成验收。完整 Chrome 在本机仍因 socket 权限失败，Headless Shell 可正常运行。

下一步应补充 Mac 真机与真实模型端到端验收，随后扩展图片/Office 成果的真实生成、预览与编辑，以及持久化执行、取消和重启恢复。不能把本次交互调整称为已对齐 Quick 全部能力。
