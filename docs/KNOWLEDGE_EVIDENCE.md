# 对话中的知识检索依据

智能体完成 knowledge_search 后，在对应回复下显示「本轮检索依据」。展开文档卡片，可以核对这次工具实际返回的提取原文、文件版本、SHA-256、起止行号和 UTF-16 偏移。它不依赖模型自行编写的引用，也不把所有检索片段都当作最终回答的论据。

## 使用

1. 在智能体中绑定知识文档并启用工具，发送需要资料核对的任务。
2. 在原生窗口批准知识读取。拒绝、取消或来源变化导致检索失败时，不新增该次片段。
3. 在回复下展开来源卡片。展开使用已批准并返回的历史片段，不读取文件、不联网、不再次发送模型，也不触发新审批。
4. 来源保存新版本后，旧卡片标出「来源已更新 · 仅历史快照」；来源移除后标出「来源已移除」。如需最新内容，请重新发起任务并批准读取。

侧栏重绘保留当前展开状态；整页重载后卡片内容仍在，默认折叠。搜索没有命中、结果达到预算、部分来源提取不完整均明确显示。Office 行号指提取文本的 LF 行，不是 Word 页码或 Excel 单元格。

## 实现与权限边界

- `services/knowledge-evidence.mjs` 仅在真实注册的 knowledge_search 成功观察事件中接收结果；校验来源当前 revision/SHA 和坐标后复制到对应 chat/run。捕获不读取任意路径，不接收模型文本中的文档 ID 作为依据。
- `src/ui/knowledge-evidence.js` 是无桥接纯视图。片段按普通文本转义，HTML、链接、图片或脚本不会在卡片内执行。
- schema1 增量字段 `chat.knowledgeEvidence`，旧对话没有此字段也正常显示；不做破坏性迁移。磁盘持久化走原 Store.save；保存错误沿原会话失败路径处理，不宣称已落盘。
- 每对话保留最近12个完整检索组，合计 JSON 字符上限96000；超限清理最早整组，不截半片段或坐标。每组沿用检索上限8片/8000字符，控制字符按JSON序列化开销计入限额。早期回复的卡片可能因清理而消失，UI明确提示。
- 记录来源是「工具检索快照」，不是逐句引用判定、事实核验或任意原文件完整预览。取消发生在一次成功检索之后，已返回快照仍可能保留在随后错误回复下；这不表示最终任务成功。
- 移除文档、解除智能体绑定不会抹除历史聊天片段；其隐私语义与历史模型回复一致。需要清除时删除相应对话。卡片不扩大未来读取权限，也不缓存审批凭证；重新检索仍走原审批。
- 新字段不写审计正文或查询，不额外送到后续模型上下文；现有工具观察按原流程用于本轮模型请求。导出对话/回复仍导出原 Markdown，不隐式加入片段；未新增证据导出功能。

原生IPC/审批/选择器、模型语义为夹具；无Mac、真实付费模型或企业MCP新验收。未重新运行Amazon软件；复用REA公开包既有静态证据，不推断其证据卡片实现。认证MCP、向量索引/知识图谱、跨Web共享核心、自主子Agent、完整Office保真仍有差距。
