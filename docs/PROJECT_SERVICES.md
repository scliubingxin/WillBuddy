# 代码项目开发服务

在「＋→代码项目与运行环境」导入完整ZIP并核对文件、实际命令和包内脚本。依赖准备、构建、测试仍是最长5分钟的普通命令。dev/start或Python main.py/app.py/server.py入口额外提供「启动开发服务（30分钟）」；每次启动均需原生目录授权及新的命令批准，运行中不表示业务已就绪。

服务最长30分钟，最多同时一个，与其他任务共享两个执行名额。第二个服务排队时不阻挡普通CLI使用空闲名额。30分钟是本次租期，不是后台daemon；退出应用停止当前执行，重启queued变paused、running变interrupted，不自动拉起或信任旧PID。需在项目页重新启动并重新确认。卡片显示预计到期、日志、停止及固定失败提示；原stderr保留供核对。

服务总输出超过1MiB不会因此杀死进程。stdout/stderr各保留最新32KiB，实时审计partial保留最新50000字符，约500ms检查点；总输出量/截断标志可核对。普通CLI仍执行原1MiB输出停止边界。取消或到期向当前子进程组发送SIGTERM，800ms后必要时SIGKILL；主动脱离该组的进程不受完整约束。这不是OS沙箱，脚本仍使用本机账号权限，安装ignore-scripts也不是安全隔离。

服务策略只在主机内部生成并绑定项目/入口/目录/精确命令；渲染层或模型给普通CLI伪造service字段不会延长时限。批准后再次核对完整源码SHA、文件路径/符号链接和授权目录真实路径；更改来源须重新导入。安装/构建/测试不能申请服务策略。记录保存失败、拒绝、取消、来源变更均不放行子进程。缺工具、依赖缺失、端口占用、权限与到期等提示仅按错误特征判断，不自动安装、换端口或重试。npm完整开发工具链、Python等仍是可选外部程序，应用主运行时已内置。

验证：330核心（新增11）、9真实Chromium相关回归、10打包测试。实际npm/Node HTTP服务、超过1.1MiB日志后HTTP仍可响应、刷新不重启、停止后端口不可达；真实缺模块、端口占用、源码变化、保存失败、拒绝、伪造策略及重启不重放均覆盖。服务测试使用很短的普通请求时限验证服务策略覆盖，并使用底层200ms实际到期测试；没有等待30分钟作墙钟验收。原生选择器/IPC/批准和模型语义仍为夹具，不代表Mac实际运行。首次旧CLI UI用例未进入新「＋」菜单，更新测试交互后完整9项通过；开发中一次闭包变量错误被核心测试拦截并修正，最终330通过。

未实现：无限期守护、自动健康探测/业务就绪、端口代理、容器隔离、自动依赖修复、monorepo选择、项目删除UI、自动重放或系统服务注册。后续先Mac原生图片/项目/签名安装验收；缺机器时推进明确来源的项目问答与环境诊断，再PDF/Office兼容。
