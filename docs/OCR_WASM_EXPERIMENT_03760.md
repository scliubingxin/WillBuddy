# 离线英文 OCR 适配实验

本轮实现 Tesseract.js 7 的 WebAssembly 图片 OCR 适配。开发环境将固定摘要的脚本、WebAssembly 核心和英文数据复制到私有临时目录，通过当前 Node/Electron 可执行文件运行子进程，输出 TSV 并复用既有词框校验。输入由既有附件授权控制，执行前后复查；子进程关闭 `fetch`，不下载语言文件。进程仍具有当前用户操作系统权限，不能称 OS 沙箱。临时目录在成功、异常和取消后清理。

实验中真实 Linux PNG 识别、ToolRuntime 授权/审计、Poppler 两页 PDF 到 WASM 英文 OCR 已通过。这个结果不代表 Mac、Apple 芯片 Electron、中文、用户原图或打包后的 GUI 已验收。中文 traineddata 未取得；PDF 仍需要本机的 Poppler 渲染程序。

## 不随源码包和应用分发的资产

上游 tesseract.js-core issue #44 提示 WASM 包含 Leptonica、图像编解码和其他库，并存在版本专属许可证与归属清单问题。基于该明确发现，源码包和应用源码复制步骤排除三个 WASM 核心、对应生成 JS 和英文 traineddata；保留适配源码、其已附许可的 JS 源文件、资源清单和构建脚本。源码包没有这七个运行时资产，默认不会启用此备选引擎。当前源码不具备可用的离线英文 OCR 引擎，不能描述为已随应用交付。

开发者可以在私有开发环境用 `scripts/prepare-ocr-wasm.py --assets <已有资源目录>` 按固定摘要准备资源，不联网，不覆盖不同内容；完整二进制对应的第三方许可证和来源未核对前，不可将这些资产纳入发布。该脚本不是安装端下载器，也不会改变打包脚本的排除规则。上游线索：https://github.com/naptha/tesseract.js-core/issues/44 。

## 测试边界

无七项资产时，真实 WASM 相关测试标记为缺少构建时资产；资源提供后真实测试通过。损坏清单、缺失或篡改资产、取消、无中文语言数据均拒绝；准备脚本对篡改、符号链接、既有不同目标和并发出现的目标拒绝覆盖。
