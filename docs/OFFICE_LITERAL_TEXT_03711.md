# WillBuddy 0.37.11 · Excel显式文本常量

## 实际实现

从权威0.37.10/v49重新获取并核验712内容文件。沿用无Electron的runtime/office-cells.mjs、Office工作区服务和私有Python/LibreOfficeKit进程，扩展现有office_update_cells的矩阵单元类型：普通字符串保持原生类型识别；单字段对象`{"text":"00123"}`要求按原样写成文本。适合工号前导零、日期样式说明、科学计数样式编号、前导空格/单引号和公式样式文字。没有新增任意UNO、IPC、联网、公式执行或持久数据字段/依赖。

主机和worker独立完整预检整个矩阵：对象必须只有text且值为字符串；仍为同一原生矩形、30行16列200格、单格400/完整JSON600个UTF16字符，拒绝控制符、孤立代理项、未知对象字段、尺寸不符和超限。对象包装也计入600字符审批预算。普通字符串仍拒绝公式样式前缀，不能靠本增量隐性增加公式执行能力。

worker仅在非空显式文本前加原生保护单引号，再执行固定EnterString；用户原文自身的前导单引号保留。空文本走空字符串清空路径，不能输入一个保护单引号代替空值。保存前从真实XLSX关系定位实际工作表和每个目标地址，非空显式文本必须是共享/内联字符串类型并逐字符等于要求；目标公式即使显示相同也拒绝。空值要求实际为空且无公式，可为原生空单元格。旧普通字符串的数字等价验证保留。

本轮标准工具定义与Office模型指令同步说明显式文本，原生确认完整展示有界矩阵和新文本语义。复用准确part/ref/HTML指纹/原生光标、选区sequence、revision/SHA、30分钟许可、逐次批准、写前持久审计、CAS及一次修改额度。输出验证器保留到手动保存重试，原生静默无操作或类型转换不一致不能绕过。多个单元格仍非原子事务，失败/取消可留私有dirty草稿而无成功发布；原件/前版保留，重启不重放。
