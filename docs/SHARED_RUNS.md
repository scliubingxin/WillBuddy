# 0.9.0 · 对话与每日任务共用持久调度

在原 CLI 队列基础上，将模型对话与每日模型任务接入同一个无 Electron 的 `runtime/run-queue.mjs`。两类模型任务按受理顺序等待，共享持久受理、状态事件、取消和重启恢复；CLI 继续保留 `commandJobs` 队列，三者共用最多两个执行名额。目前不是三类任务统一 FIFO，也未统一原 Web 的存储/执行引擎。

## 用户可见变化

- 对话遇到执行名额占满时显示排队，刷新后打开原任务仍可停止。自动化页新增真实模型执行队列，显示对话/每日任务状态，并提供停止请求。
- 每日任务现在可在排队或运行中停止。供应商忽略取消而返回的迟到结果不会产生新成果、覆盖任务结果或触发完成通知；真实 HTTP 中止已验收。
- 同一逻辑请求 ID 返回已有状态/等待已有执行，同 ID 改内容被拒绝。同一任务的同一个定时时刻使用确定性 ID，重复触发不会重复调用模型/生成成果。
- 关闭后重新打开：旧排队变为 paused，已领取/停止中变为 interrupted，不恢复 worker、模型请求、工具审批或外部进程。可以在原对话重新发送，或手动重新运行每日任务；这会生成新 ID，操作仍需逐次审批。不能声称实现模型工具步骤续跑。
- 定时时刻在受理时持久推进；重启不会补跑同一个旧请求。应用持续运行到下一次新的 nextRun，才正常受理下一轮；休眠时尚未受理的到期任务在应用恢复后受理一次。
- 排队任务不能被删除，队列内的每日任务不能修改定时开关，模型配置也需等待已有模型任务结束/取消。文件授权可撤销，附件在实际出队时重新检查/读取；读取等待期间取消或撤销，也不会随后发送给模型。

## 数据与接口

工作空间继续 schema 1，增量字段 `runJobs`；旧用户数据、原 Web/Python、Actwill AI 密钥身份、actwill IPC、logo与白蓝主题保持。迁移在恢复/队列初始化时补空数组，没有 SQL 或全量历史重写。

每条记录含 id/kind/ownerId/label/fingerprint/createdAt/status/revision/events/finishedAt。SHA-256 fingerprint用于同 ID 请求冲突检测；不保存 worker函数、API Key、完整文件正文或审批凭证。提示词和附件引用仍在原聊天记录中，队列标题含提示词前80字。原 workspace.json 的明文与加密密钥策略不变。

`run.status` 事件为 version 1，含 jobId/kind/ownerId/sequence/previous/status/time，每条最多50事件；revision递增，界面拒绝旧版本覆盖更新状态。SSE文本事件继续独立传输，取消和完成的任务不会被迟到片段复活。模型队列最多20条未完成记录，历史保留最近200条及仍活跃记录；去重以当前保留记录为范围，不能保证第三方副作用的全局 exactly-once。

受理与运行状态保存成功后才会进入模型/工具；失败关闭并释放名额。用户取消会立即置 abort，等待实际 worker停止后才释放运行名额，避免忽略取消的供应商导致并发超限。超时从实际出队后计算120秒，不占用排队等待时间；等待中的请求可手动停止。

preload仅新增明确的 cancelTask/cancelRun。原生可信来源校验、最小权限桥和逐次工具审批保持。main只组装服务并唤醒队列/每日调度，不复制业务执行逻辑。

## 实际验证（2026-10-22）

- 81项 Node/JSDOM：新增16项队列/混合执行/权限/故障测试及1项刷新/过期状态界面测试。混合容量测试实际运行 Node CLI；包括重复定时发生、重启不重放、磁盘故障不调用模型、排队/读取期间撤销授权、预读附件期间取消、迟到响应禁止成果/通知。
- 5项真实 Chromium：新增共享调度→真实HTTP模型夹具取消、刷新排队对话后停止；原SSE/Markdown/HTML、工作区、实际Node CLI及浏览器CDP可信输入回归通过。原生桥、审批和模型内容仍是夹具，不冒充Mac或真实付费模型。
- 7项Python打包边界与35项原Python执行器回归通过。离线包继续只构建arm64，静态校验不等于原生Mac严格资源密封/Gatekeeper/启动或公证验收。

复现：`npm --prefix desktop test`；设置 `CHROME_PATH` 后运行 `test:runs`、`test:streaming`、`test:workspace`、`test:commands`、`test:browser`（容器浏览器可另设CHROME_TEST_NO_SANDBOX=1，产品sandbox不变）；`python3 -m unittest discover -s scripts/tests -v` 与 `python3 tests/local-runner-test.py`。

## 仍待接续

CLI 与模型队列尚为两个队列；共享容量，不保证跨队列全局公平调度。Web/桌面尚未统一业务核心；没有OS后台服务、关机执行、跨设备事件同步、进程续跑或自动重试工具。无目标Mac/账户时，继续推进桌面MCP、授权文件写入/验收和真实Office成果，并覆盖队列间公平与统一事件契约；获得Mac环境先做严格签名/安装启动/原生审批、真实模型与Codex CLI验收。沿用已有REA静态证据，不新增Amazon内部实现推断。
