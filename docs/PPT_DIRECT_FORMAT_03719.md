# PPT 选中文字的真实字号与字色编辑

WillBuddy 0.37.19 在文档侧栏的标准工具循环新增 `office_format_presentation`。先双击 PPT 普通单段文本框进入文字编辑，用全选或方向键/Shift 选中文字，再在 AI 侧栏发送例如“把选中文字设为 24.5pt 红色，不改文字”。模型调用工具后仍需原生逐次批准；真实内核设置字号或字色，再读取实际保存的 PPTX 验收，通过后才发布新 revision。不是仅修改预览 CSS，也不依赖模型自称完成。

## 实际范围

- 参数仅 `fontSize`（6–96pt、0.5pt 步长）与 `fontColor`（#RRGGBB），至少一项；可以分别或同时设置。主机与 Python 工作进程独立检查，固定 `.uno:FontHeight`/`.uno:Color` 命令，不能传入任意 UNO 名称。
- 当前页必须唯一对应所选文字，目标是普通、顶层、单段文本框，选区直接格式一致；最多50页、2000形状、10万文字、单行选区12000字符。混合格式、分组、表格、域、链接、复杂效果、显式主题字体等沿原保守拒绝策略。
- 验收器在原生修改前装入会话：全部幻灯片文字、形状顺序和类型保持；选区逐字符必须含请求字号和 RGB；未请求的已知直接字号/字色/粗斜体/下划线等与其他简单文本框已知格式保持。允许内核拆合 run，不能把 run 数量当文字坐标。已知段落/本地层级默认格式会解析；不覆盖完整母版/版式/主题级联、复杂对象几何、所有样式或像素保真。
- 不新增手动格式工具栏或 IPC 权限，复用现有文档聊天与模型路由。`office_format_selection` 仍仅处理 Word，Excel 原工具不变；新工具与替换/表格等修改共用每次文档聊天请求一次修改额度。

## 执行与故障边界

页面、真实文字选区类型、sequence、revision/SHA、30分钟授权在审批与持久 running 审计后再次核对；worker 独立核对 part 和 expectedSelection。拒绝、旧选区、取消、审计存储失败不发格式命令。保存的 PPTX 没改、改错或丢格式不能提交；私有 dirty 草稿保留相同验收器，显式保存不能绕过。磁盘恢复后可以显式保存重试，旧原件和前5版保留，不自动重放。

这不是内核/磁盘/审计的原子事务，故障磁盘回滚仍可能失败，完成审计失败不能撤回已持久成果；不扩大已有能力承诺。

## 验证与环境

本轮使用真实 Linux LibreOfficeKit 26.8alpha、实际 Node HTTP 标准工具调用夹具和生产 Chromium Office 页面。独立 python-pptx 检查实际导出文件：仅 TARGET 改为24.5pt红色，前后文字仍32pt蓝色，粗体/斜体/下划线和其他页文字保留；分别设置单属性也核验。包含拒绝、错误参数、页/选区漂移、取消、审计失败、native no-op、磁盘失败重试与 Store 重载。

实际计数和构建摘要见 `validation/v0.37.19.json` 及同名前缀日志。原生 IPC/审批、Keychain 和模型语义为夹具；未验收付费模型、Mac 所带26.8.1.1、中文 IME/字形、Mac严格签名/Gatekeeper或安装速度。安装端不增加依赖，源码与离线应用仍含全部旧功能。
