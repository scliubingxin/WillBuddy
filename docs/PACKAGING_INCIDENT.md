# 0.5.0 安装签名故障与 0.6.0 打包修复

2026-10-21 用户实测报告：安装/解压目录存在 `.BC.T_*` 普通文件和 `.BC.D_*` 符号链接；`codesign --verify --deep --strict` 在 Electron Helper 子组件报告 `a sealed resource is missing or invalid`，清理后通过。这是用户提供的 Mac 验收证据，本构建主机不能独立复验。尚未独立确定残留是在构建、传输还是解压阶段产生；不能把启动被拒绝直接推断成系统删除应用目录的原因，后者仍需系统日志确认。

已确认的代码缺陷：旧打包器递归 zip 遍历实际目录，校验只遍历 OFFLINE-MANIFEST 的每个条目，没有要求 ZIP 的实际文件集合与清单完全相等。因而“清单内 282 条目全部匹配”不能排除额外残留。0.6.0 修复这个明确的验证缺口。

修复：

1. 签名前和签名后清理已知 `.BC.*`、`._*`、`__MACOSX`、`.DS_Store` 和 rcodesign 临时副本；资源封印若引用残留则失败，不能偷偷删除已密封文件。
2. 根据冻结的明确文件清单创建 ZIP，普通文件先写、Framework 链接后写；不递归跟随链接，不打包快照后新增的文件。
3. 严格要求 ZIP 的非目录条目集合等于应用清单加 5 个指定配套文件；拒绝残留、额外条目、重复/大小写冲突路径、逃逸或损坏的链接、摘要/尺寸和执行位变化。
4. 安装脚本发现残留时停止，仍在复制后的临时应用上执行原生 `codesign --verify --deep --strict`，通过才替换旧版；不删除用户配置，不移除隔离标记，不关闭 Gatekeeper。
5. 安装说明改为先在下载/个人目录的新文件夹中完整解压，再移动 app；不直接向 /Applications 解压，不把说明/许可证散落到应用程序目录。
6. macOS GitHub Actions 增加 fresh `ditto` 解压、残留检查及原生严格签名校验；未通过不上传安装成果。本轮尚未运行该远程工作流。

验证：7 项 Python 边界测试通过，涵盖普通文件与链接残留、全部清单摘要仍正确但多出文件、封印引用残留、逃逸链接、大小写冲突、重复路径、篡改及执行位丢失。重建 ZIP 共 287 个非目录条目：282 个应用条目（14 个链接）及 5 个配套文件，无残留。官方 Electron SHA256、15 个 Mach-O / 51216 代码页、篡改负例、ZIP CRC/完整集合/链接/执行位均通过。

范围：这些是 Linux 上的可复现打包与静态验证，不等价于 Mac 原生 codesign、Gatekeeper、公证或真实启动通过。签名仍为 ad-hoc。参考用户实机证据进行修复后，仍需在目标 Mac 对新包做严格签名和启动验收。
