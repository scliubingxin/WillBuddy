# WillBuddy 0.13.0：导入 Word 的片段编辑与保留边界

2026-10-22。本轮回应“生成后还需要在工具内编辑已有 Office”的缺口：新增导入 DOCX 的片段级编辑，不把整个文件重新转成 HTML 后重建。0.12 的真实 GenOffice HTML→DOCX 子引擎与新建写作画布继续保留。

## 操作

1. 成果中心“导入文档”选择 DOCX，原件不覆盖。
2. 点击“Word 分段编辑”，或回复中的同名按钮。点击有虚线边界的文字片段可直接改字；点击片段后用 B/I 设置该片段的直接粗体、斜体。段落按正文、页眉、页脚列出，表格内文字也可修改。
3. 复杂段落显示只读原因，不提供可编辑输入；保存时重新检查坐标。界面不是分页预览，也不解析继承自样式表的最终字体。工具栏对整个文字片段生效，不是任意字符选区格式。
4. 保存经原生确认后成为新版本，下载真实 DOCX；前五版可另行导出。多任务、独立停止、流式输出和旧文档能力保留。

## AI 工具

`document_read` 经审批返回 `wordEditing`：部件名、段落/片段序号、原始片段 SHA-256、文字、直接粗体/斜体。整体结构超过12000字符或超过500段/2000片段时不发送半截结构，返回不可用提示。内容仍是不可信资料，不应作为指令。

新 `document_patch` 接受实际坐标与 `anchor`、`expectedRevision` 和所需 `text` / `bold` / `italic` 字段。不能猜测坐标，字段、重复目标、单行文本、10000字符/片段、100处/本机保存等上限由主进程校验。模型每批修改参数最多600字符，过长需拆批重读；审批展示完整这一批参数，不用大弹窗隐藏按钮。审计移除修改正文、读取的结构和文字，仅保留结果摘要。

画布 Word 继续用 `document_write`，不得用片段工具使 HTML 源失效。原来的“编辑内容”兼容入口仍可用，其整段修改采用首片段样式；优先使用“Word 分段编辑”保留既有其他片段格式。

## 保留与失败行为

`runtime/word-structure.mjs` 独立解析经既有ZIP/XML/CRC/宏/外链门禁检查的OOXML，仅改变指定 `w:t` 与显式 `w:b` / `w:i`。保留其他 run 属性，如字号、字体、颜色、下划线；不删除、重建段落、表格、节或图片。未修改 ZIP 部件的解压后字节与 SHA-256 逐个复验。受改 XML 部件会重新序列化，因此不承诺原ZIP压缩字节或整份XML字节完全一致；测试对未改段落子树单独比较。

含图片、制表符、换行、域、链接、书签、复杂嵌套结构的段落，以及修订/内容控件内的段落，保守设为只读。数字签名包拒绝编辑，避免把失效签名当有效签名。现阶段不增删/重排段落和表格，不编辑图片、批注、修订；不宣称任意 DOCX 无损保真。

候选在审批前生成，审批后仍检查当前版本与单次凭证。取消、拒绝、并发修改、磁盘失败均不发布候选；保存失败恢复旧记录。导入原文件始终不写回；无需安装 Python、Office 或 npm。开发独立解析测试使用 Python，不是最终用户依赖。无新增数据模式或外部服务。

## 验证与后续

136项核心（新增13项）、9项真实Chromium（新增1项）、7项打包Python通过。新增标准HTTP模型协议夹具→read→patch→真实DOCX、直接格式/表格/页眉修改、图片/其他部件SHA、未改段落子树、拒绝/取消/冲突/磁盘回滚、模型结构大小边界与界面纯文本防注入测试。生产浏览器导入→编辑→导出由独立python-docx检查文字、直接格式、既有字号颜色、表格、图片和页眉页脚，磁盘重载后再次打开通过。

原生IPC/审批、模型内容为夹具；没有付费模型或Mac真机/严格签名/Gatekeeper/Word-WPS渲染验收。当前GenOffice仍是已集成的HTML→DOCX子引擎，新导入编辑采用WillBuddy自己的受限OOXML补丁，并非完整上游编辑器。

下一步：原生Mac与实际模型/Word验收优先；无目标机则增加明确限定的段落/表格结构编辑，随后电子表格公式引擎与保真页面预览。保持跨端核心/MCP与自主并行子任务为未完成项。
